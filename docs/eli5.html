cli-harness

A safe remote control for a grown-up computer program

Explained like you are 5.

1. The problem

AI agents are clumsy with apps and text commands.

Clicking around an app is slow and easy to get wrong. Typing a command line program's options from a guess is risky too. Guess wrong, and something real can break.

2. What cli-harness does

It wraps a program you already have in a remote control.

You pick one program that is already installed, like sqlite3. The skill builds a small, tested wrapper that talks to the real program. It also writes an instruction card so an agent knows which buttons exist and how to press them.

You type /cli-harness sqlite3 and get a folder called harness-sqlite3.

3. The story in 7 steps

The recipe is called the SOP. The steps go in order, and none are skipped.

  1. Phase 0: Can we even do this?Look for the program. Not installed? Stop. On the do-not-touch list? Stop. Does it move money, delete your stuff or touch passwords? Stop.
  2. Phase 1: Look at itRead the program's own help. Pick at most 6 buttons for the remote. Mark the ones that change things.
  3. Phase 2: Make a planWrite down what we will try and how we will prove it worked. This happens before any code.
  4. Phase 3: Build the remoteMake the wrapper. Every button that changes things gets a practice mode called --dry-run. The wrapper calls the real program and never pretends to be it.
  5. Phase 4: Test itRun the tests. They look at the real result, like a file's bytes or a count of rows. A missing program makes a test fail, not skip.
  6. Phase 5: Write the instruction cardA script makes the card (a file called SKILL.md) straight from the code. Nobody types it by hand.
  7. Phase 6: Are we done?Run the checker and the tests. Both must pass. See below.

4. The safety rules

  • Installed only. It uses programs already on your computer. It never clones, downloads or installs anything.
  • A do-not-touch list. Programs like rm, dd, sudo, git, curl and ssh are refused before they ever run. Anything that moves money, deletes user data or touches credentials is refused too.
  • Practice first. Buttons that change things have --dry-run, which shows what would happen without doing it. Agents press that first.
  • Fail, do not skip. If the real program is missing, the test fails loudly. Skipping a test is not allowed, and the checker rejects skip markers.
  • Check the actual output. A test never trusts "it said OK" alone. It opens the file, counts the rows or measures the length.
  • No secret back door, and no hiding errors. There is no "run anything" button, and errors always end with a non-zero exit.

5. How we know it is done

Two things must both be true.

Overall: PASS (9/9 checks)

The checker passes all 9 of its checks, and the tests are green.

Nothing else counts. Not "it looks fine" and not "it ran once."

6. Who thought of it first

The method is inspired by HKUDS CLI-Anything (Apache-2.0) and its paper, arXiv 2606.03854. cli-harness did not copy their code. It is a new, smaller take on the idea.
