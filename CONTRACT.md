# CONTRACT v1: cli-harness

This is the frozen interface. Tests are written from this file, and the code is written to pass those tests. If something here is wrong, flag it. Do not work around it.

## What the skill does
`/cli-harness <binary>` turns ONE executable that is already installed on PATH (for example `sqlite3` or `ffmpeg`) into a harness. A harness is a thin, tested Click wrapper that shells out to the real binary, plus an auto-generated SKILL.md, so agents can drive the binary safely. The skill never clones, downloads or pip-installs anything.

## Harness layout (what the SOP produces, at `./harness-<binary>/`)
```

cli.py            Click app rendered from wrapper_cli.py.tmpl, then extended with commands
TEST.md           written BEFORE tests; must contain a "## Workflows" heading
tests/test_<binary>.py
SKILL.md          generated by gen_skill.py, never hand-written
```

## scripts/probe.py
CLI: `python3 probe.py <binary> [--timeout SECONDS]` (default 10)
- Resolves the binary with `shutil.which` only. No hardcoded paths.
- Runs every subprocess with `stdin=subprocess.DEVNULL` (sqlite3 otherwise waits on stdin) and the timeout. Stdout and stderr are combined.
- version: tries `--version`, `-version`, `-V` in order. The first attempt with non-empty output wins, and the value is the first non-empty line. Otherwise null.
- help: tries `--help`, `-help`, `-h` in order. The first attempt with non-empty output wins. The text is truncated to 20000 chars. `help_flag_used` is the flag that won, or null. Non-zero exit codes are accepted when there is output.
- Exit 0 and stdout JSON: `{"binary","path","version","help","help_flag_used","denylisted":false,"deny_reason":null}`
- Not on PATH: exit 2, stdout `{"error":"not_found","binary":...}`
- Denylisted: exit 3, stdout `{"error":"denylisted","binary":...,"deny_reason":str}`. The binary is never executed.
Python API: `DENYLIST: frozenset[str]` (it must contain at least rm, rmdir, dd, mkfs, diskutil, shred, srm, sudo, su, kill, killall, launchctl, security, git, gh, curl, wget, ssh, scp), `resolve(binary) -> str|None`, `probe(binary, timeout=10) -> dict` (the same dict as the stdout JSON; raises nothing for not_found/denylisted, it returns the error dict), `main(argv=None) -> int`.
The denylist check uses `os.path.basename(binary)`.

## scripts/gen_skill.py
CLI: `python3 gen_skill.py <harness_dir> [--check]`
- Reads `<harness_dir>/cli.py` and parses it with `ast` ONLY. It never imports or runs the file.
- Reads `<harness_dir>/harness.json`.
- Writes `<harness_dir>/SKILL.md` and exits 0. With `--check` it writes nothing: exit 0 if the existing SKILL.md equals the fresh render, exit 1 otherwise and print "SKILL.md is stale".
Python API:
- `parse_cli(source: str) -> dict` returns `{"group": str|None, "group_options": [{"flag","help"}], "commands": [{"name","func","help","options":[{"flag","help"}],"arguments":[str]}]}`
  - group: the name of the function decorated with `@click.group(...)`
  - commands: functions decorated with `@<group>.command(...)` or `@click.command(...)`, in source order. The name is the first positional string arg of the decorator or `name=` kwarg, else the func name with `_` replaced by `-`.
  - help: the first line of the docstring, stripped, or "".
  - options: from `@click.option(...)`. flag = the first positional string that starts with `--` (else the first positional string). help = the `help=` kwarg string, or "".
  - arguments: the first positional string of each `@click.argument(...)`.
  - decorator lists are read top to bottom (source order).
- `render_skill(meta: dict, parsed: dict) -> str` is deterministic: no timestamps, and the same input gives byte-identical output. Format:
```
---
name: <binary>-harness
description: Agent harness for the <binary> CLI (<version>). <meta.description>
---

# <binary> harness

Generated by cli-harness gen_skill.py from cli.py. Do not edit by hand.

## Rules for agents
- Always pass --json and parse stdout.
- Run any mutating command with --dry-run first: <comma list of meta.mutating, or "none">.
- Non-zero exit means failure. Never treat exit 0 alone as proof the output is right.

## Commands
| Command | Description | Options | Arguments |
|---|---|---|---|
| <name> | <help> | <flags joined ", " or "-"> | <args joined ", " or "-"> |
```
  The file ends with a single trailing newline.
- `main(argv=None) -> int`

## scripts/validate.py
CLI: `python3 validate.py <harness_dir> [--json]`. Exit 0 if every check passes, else 1.
Checks, in this order, with these exact names:
1. `harness_json`: harness.json exists, is valid JSON and has the keys binary, version, description, mutating (a list)
2. `cli_parses`: cli.py exists and `ast.parse` succeeds
3. `json_flag`: the click group in cli.py has an option whose flag is `--json`
4. `dry_run`: every command named in harness.json `mutating` exists in cli.py and has a `--dry-run` option
5. `backend_call`: cli.py source contains `shutil.which` and `subprocess`
6. `test_plan`: TEST.md exists and contains a line that starts with `## Workflows`
7. `tests_exist`: at least one `tests/test_*.py`
8. `no_skip`: no tests/*.py file contains `pytest.skip`, `mark.skip`, `skipif` or `importorskip` (missing backend must FAIL, not skip)
9. `skill_md_sync`: SKILL.md exists and equals `render_skill(harness.json, parse_cli(cli.py))` exactly
Human output: one line per check, `[PASS] <name>: <detail>` or `[FAIL] <name>: <detail>`, then a final line exactly `Overall: PASS (9/9 checks)` or `Overall: FAIL (<passed>/9 checks)`.
`--json` output: `{"checks":[{"name","passed","detail"}],"passed":int,"total":9,"overall":"PASS"|"FAIL"}`
Python API: `CHECK_NAMES: list[str]` (the 9 names in order), `run_checks(harness_dir) -> list[dict]`, `main(argv=None) -> int`. Imports gen_skill from its own directory (sys.path insert of `Path(__file__).parent`).

## templates/wrapper_cli.py.tmpl
Plain text with exactly two placeholders, `{{BINARY}}` and `{{DESCRIPTION}}`. Rendering is `str.replace`. After substitution it must be valid Python that:
- defines `BINARY = "{{BINARY}}"`
- defines `run_backend(args: list[str], input: str|None=None, dry_run=False) -> dict`
  - resolves with `shutil.which(BINARY)`. When missing it raises `click.ClickException` whose message contains "not found on PATH" and the binary name.
  - when dry_run is set, it returns `{"dry_run": True, "would_run": [BINARY, *args]}` and does NOT execute.
  - otherwise it runs `subprocess.run([path,*args], input=input, capture_output=True, text=True, stdin=DEVNULL if input is None)`, returns `{"returncode","stdout","stderr"}`, and raises `click.ClickException` with stderr when returncode != 0. Failures are never swallowed.
- root `@click.group()` function named `cli`, with `@click.option("--json", "as_json", is_flag=True, help="Machine-readable JSON output.")`, storing `ctx.obj = {"json": as_json}`
- `emit(ctx, data: dict)`: prints `json.dumps(data)` when json mode is on, else a human-readable form
- a `version` command (read-only) that runs the binary's version flag through run_backend and emits `{"binary": BINARY, "version": <first non-empty line>}`. It tries `--version` then `-version`.
- `if __name__ == "__main__": cli()`
Running `python3 cli.py --json version` from a rendered sqlite3 template prints one JSON object with exit 0. With a binary that does not exist, it exits non-zero and stderr contains "not found on PATH".

## templates/TEST.md.tmpl
Placeholders `{{BINARY}}`. It has the sections `# Test plan: {{BINARY}} harness`, `## Workflows` (a numbered list of realistic workflows, each with the artifact check that proves it worked), `## Artifact checks`, `## Results`.

## SKILL.md (the skill itself) and SOP.md
SKILL.md body: "Read SOP.md in this directory before doing anything. Do not improvise." plus the invocation and the one-paragraph scope. SOP.md phases:
0. Refuse checks: run probe.py; exit 2 or 3 means stop and tell the user.
1. Probe: read the help text and decide the command surface (max 6 commands for v1). Mark which ones mutate.
2. Plan: copy TEST.md.tmpl and write the workflows plus artifact checks BEFORE any code.
3. Build: render wrapper_cli.py.tmpl, add commands, and every mutating command gets `--dry-run`. Call the real binary and never reimplement it.
4. Test: write tests/test_<binary>.py from TEST.md. Tests verify artifacts (file magic bytes, row counts, ffprobe durations), never exit codes alone. A missing binary FAILS, never skips. Run pytest and paste the summary into TEST.md `## Results`.
5. Document: run gen_skill.py. Never hand-edit SKILL.md.
6. Done = `validate.py` prints `Overall: PASS (9/9 checks)` AND pytest is green. Nothing else counts.
Safety rules: never wrap a binary that moves money, deletes user data or touches credentials, even if it is not on the denylist. No passthrough "raw" command. Errors exit non-zero.
